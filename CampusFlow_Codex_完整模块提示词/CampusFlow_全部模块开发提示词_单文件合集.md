## 强制开发规范

## A. 开始前必须遵守的共同规则

你是资深全栈工程师、React/TypeScript 架构师、跨平台工程师与测试工程师。请直接在当前仓库中执行以下任务；如仓库为空，则先建立可运行项目。

1. **先检查**：目录、依赖、git 状态、运行脚本、数据模型、已有功能和测试；如用户已有实现，以实际仓库为准，先做兼容性分析。
2. **保持不破坏**：严禁为了实现本模块重写整个项目、删除无关模块、清空 IndexedDB、静默改变已有持久化字段或破坏旧备份。所有 schema 变更使用版本化迁移与回滚/恢复策略。
3. **共享核心**：React + TypeScript + Vite + Tailwind CSS + shadcn/ui + Zustand + Dexie/IndexedDB；使用 Capacitor 为 Android/iOS 提供原生壳，使用 Tauri 2 为 Windows/macOS 提供桌面壳。保留可扩展适配器，优先复用 UI、业务规则、验证与测试。技术可依据现有仓库适配，不得无理由换栈。
4. **离线优先**：没有互联网和账号也能使用核心课表；跨设备自动同步、共享权限、短链、在线协作等需要真实授权服务时，必须清楚拆成后续可选层，不得伪造成功结果。
5. **平台真实能力**：通过 `PlatformCapabilities` 检测权限/特性；不支持时隐藏或禁用按钮并说明原因。iOS/macOS 原生构建需 macOS/Xcode，不得在 Windows 假装产出了已签名的安装包。
6. **隐私优先**：采用最小数据原则，导出、分享、截图与日志默认保护个人课程、教室、座位、备注。不得把用户 API Key、OAuth Token、凭据打包到 Web 静态代码、同步数据或明文日志中。
7. **交互完整**：界面控件必须有可运行的动作；有加载/错误/空状态、取消和撤销入口；中文为默认语言，兼容英文；支持触摸、键盘、屏幕阅读器及减少动画。
8. **保守执行**：遇到依赖缺失或平台 API 不可用，优先实现可运行的接口、单元测试和明确标注的功能降级；不要用假数据冒充正式结果，不要用不存在的 SDK/API。
9. **先测试再汇报**：完成后执行当前环境可用的 lint、typecheck、unit、build 和相关端到端测试。未执行的检查如实列明原因。
10. **阶段提交**：只完成本模块，不要顺带实现其他大模块；输出更改文件、迁移影响、测试结果、已知限制及下一阶段建议。

# CampusFlow — 技术架构、数据规范与全模块共用约束

## 0. 产品定位

中国大学生跨平台智能课程表软件，支持 Web / PWA、Android、iOS、Windows、macOS。一套核心规则驱动：教学周、单双周、指定周、临时调课、考试、个人日程；本地优先，在没有账号和网络时也完整可用。**未被用户选择的模块：09 课程笔记与学习资料、10 校园地图与教室导航，本轮不开发。**

## 1. 推荐的 Monorepo 结构（Codex 可根据现有仓库适配）

```text
campusflow/
├─ apps/
│  ├─ web/                 # React + Vite，Cloudflare Pages & PWA
│  ├─ desktop/             # Tauri 2，Windows / macOS
│  └─ mobile/              # Capacitor，Android / iOS
├─ packages/
│  ├─ domain/              # 学期、周次、课次、冲突、空闲区间纯函数
│  ├─ data/                # 仓储、Dexie、迁移、备份
│  ├─ ui/                  # 共享组件、主题、无障碍
│  ├─ integrations/        # AI、日历、导入、同步接口与适配器
│  ├─ platform/            # 平台能力检测、通知、Widget、文件操作
│  └─ testing/             # fixture、合约测试、跨平台案例
├─ docs/
└─ README.md
```

如项目已建立单包 React 工程，则先做适配，不为目录结构而大规模重构。

## 2. 关键领域关系

- `Semester`：学期、教学周起点、教学周总数、周起始日、教学日历规则。
- `TimetableProfile`：同一学期内的课表版本/个人方案。
- `Course`：课程身份、名称、类别、默认教师/地点、主题配置。
- `CourseSession`：某课程的一条重复上课规则，星期、节次范围、指定周集合/单双周。
- `CourseException`：某个具体发生日期的停课/补课/调课或属性覆盖，关联原课次，保留审计记录。
- `ClassTimeSlot`：学期/模板级节次时刻映射，允许周内不同作息。
- `CourseOccurrence`：**派生**视图；实体 ID + 确切日期/时间/地点/教师/变更标志，所有 UI、通知、冲突、统计、ICS 从此读取。
- `Exam`、`Task`、`PersonalEvent`：彼此独立的实体，引用课程使用可空外键。
- `ReminderRule`、`ReminderInstance`：规则和待触发通知分离；课程变动需失效重建。
- `ShareSnapshot`、`AvailabilityInterval`、`SyncAdapter`：分享与同步隔离，不强制所有用户创建账号。
- `ThemeDefinition`、`UserPreference`、`BackupManifest`：版本化设置与备份。

## 3. 时间规则与确定性业务引擎

1. 优先使用日期明确的计算库（Codex 先核对本项目依赖与最新文档）；将**本地日期/本地时刻/时区/时间戳**明确分离，不靠字符串比较日期。
2. 教学周由学校校历定义，不等同 ISO 周号。使用教学周第一天 + 起始日 + 非连续教学周调整规则建立日期与周次映射。
3. 多个 CourseSession 描述同课不同星期、不同教学周；周次规则以标准化集合/谓词处理（单、双、全部、指定周）。
4. `CourseOccurrence` 以日期范围按需展开，并顺序应用校历、停课、调课、补课及单次地点/教师覆盖；保留 sourceSessionId 和 exceptionId，避免导出与统计重复计数。
5. 冲突检测统一采用半开区间 `[start, end)`；相邻课程（上一节结束恰好下一节开始）不算冲突。支持用户显式保留冲突。
6. 取消课次不能出现在“实际课程数/剩余课次/通知”中；临时补课必须出现。原始规则不被例外覆盖直接修改。
7. 编辑/删除课程、调课、补课、考试或日程后，通过领域事件通知视图、统计、Widget 和系统提醒重算。
8. 课程分享、导出、日历同步均由可验证的数据视图生成，不由 AI 直接推测。

## 4. 跨端能力矩阵

| 能力 | Web / PWA | Android (Capacitor) | iOS (Capacitor) | Windows (Tauri) | macOS (Tauri) |
|---|---|---|---|---|---|
| 课表 CRUD/周次算法/本地数据 | 必须 | 必须 | 必须 | 必须 | 必须 |
| 系统通知 | 浏览器在支持条件下 | 原生本地通知 | 原生本地通知 | 系统通知 | 系统通知 |
| 原生桌面/主屏组件 | 不支持原生桌面 Widget | 原生 AppWidget | WidgetKit 扩展 | 可选悬浮窗/托盘 | 可选菜单栏/Widget 扩展 |
| 离线使用 | Service Worker + IndexedDB | WebView 持久化+原生适配 | WebView 持久化+原生适配 | 持久化本地仓储 | 持久化本地仓储 |
| 文件导入/备份 | File API | 系统文件选择器 | 系统文件选择器 | 本地文件 API | 本地文件 API |
| 自动同步 | 可选，需授权端点 | 可选 | 可选 | 可选 | 可选 |
| 打包条件 | Node 构建 | Android SDK | macOS + Xcode | Windows 工具链 | macOS + Xcode |

注：IndexedDB 在 WebView/桌面 WebView 的数据可靠性、备份、权限与浏览器清理行为可能不同，必须经平台适配和真机测试决定是否增加 SQLite 原生仓储；不得默认完全等同。

## 5. 安全、隐私、授权

- 不强制账号。AI 的外部请求、课表分享、第三方日历授权在用户明确同意后才执行。
- API Key、OAuth access/refresh token 不存公开 Web bundle，不放 JSON 备份，不写日志。用户自带 Key 如要在浏览器直接调用须核查 CORS、凭据暴露风险；优先平台安全存储、受控代理或明确说明功能限制。
- 分享仅用户勾选的字段；默认遮蔽座位号、成绩、私人备注、私密课程名称/地点。
- 公开订阅链接、邀请权限、撤销授权、群组协作 **必须有真实服务端鉴权**。无后端时只支持文件交换和本地只读快照。
- AI 输出为**提案而非命令**，必须 schema 验证、展示差异、用户确认、可撤销，外部输入视为不可信。
- 外部日历使用正式认证授权流程与权限最小化；断联后本地课表仍可用。
- 图片、音乐、吉祥物等资产使用自有、原创或明确授权素材。

## 6. 数据版本化、恢复与 QA

- 将数据 schema 与导入备份 manifest 分别版本化。每次迁移先验证旧版本，迁移失败可恢复原快照。
- `Repository` 为所有模块暴露 typed CRUD 和事务；禁止 React UI 直接随意拼接数据库表读写。
- 最少测试覆盖：20 周/单双周/跨学期/调课/补课；多人空闲交集；重复日程；导入导出往返；通知重排；深浅主题和键盘；离线恢复、数据迁移与同步冲突。
- 全部操作提交前运行实际可用的 `typecheck`、`lint`、`test`、`build`，并附运行结果。不要编造 Windows 上已经完成的 iOS/macOS 打包。

## 7. 每个模块的统一质量门槛

先列变更计划 → 实施最小完整路径 → 增补数据验证/错误状态 → 跑测试 → 提供手动验收操作 → 更新文档 → 汇报已完成/平台受限/待配置。新增功能不可破坏之前已完成模块和历史数据。

## 集成顺序注意
